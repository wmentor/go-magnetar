# Agent Tools

go-magnetar dynamically generates dedicated tools for each available subagent. Instead of a single generic `agent` tool, you get specific tools like `agent_code_reviewer`, `agent_security_analyzer`, etc.

## Signature

Each agent-specific tool follows this signature:

```
agent_<name>(message: string) -> string
```

Where `<name>` is the normalized agent name (hyphens replaced with underscores).

## Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `message` | string | The message to process by the agent. This should contain the task or question to delegate. |

## Tool Naming

Agent tool names are generated by:
1. Taking the agent name (e.g., `code-reviewer`)
2. Replacing hyphens with underscores (e.g., `code_reviewer`)
3. Adding the `agent_` prefix (e.g., `agent_code_reviewer`)

### Examples

| Agent Name | Tool Name |
|------------|-----------|
| `code-reviewer` | `agent_code_reviewer` |
| `security-analyzer` | `agent_security_analyzer` |
| `test-agent` | `agent_test_agent` |

## Tool Description

Each agent tool's description is automatically taken from the agent's `description` field in its YAML configuration. This helps the LLM understand when to use each tool.

### Example

If you have an agent defined as:

```yaml
---
name: security-analyzer
description: Analyzes repositories for security vulnerabilities
tools:
  - github_repo
  - web_search
---
You are a security expert...
```

The generated tool will be:
- **Name**: `agent_security_analyzer`
- **Description**: "Analyzes repositories for security vulnerabilities"
- **Parameters**: `message` (string)

## Usage

Agent tools are called automatically by the chat agent when it determines that a subagent is needed to handle a request. You don't need to manually invoke these tools; the agent will use them when appropriate.

### Example

If you ask a question that requires domain-specific knowledge or a specialized workflow, the agent might delegate the task to a subagent:

```text
User: Can you analyze this GitHub repository for security issues?
Agent: [Uses agent_security_analyzer tool to delegate to security-analyzer agent]
```

## How It Works

1. At startup, go-magnetar scans all available agents from `.go-magnetar/agents/` directories
2. For each non-disabled agent, a dedicated tool is registered with the name `agent_<name>`
3. The tool's description is taken from the agent's metadata
4. When the LLM calls an agent tool, the corresponding subagent is invoked with the message
5. The subagent processes the message using its own prompt and available tools
6. The subagent returns a response
7. The main agent receives the response and incorporates it into the final answer

## Benefits

This approach provides several advantages:

1. **Better LLM understanding**: The LLM sees specific tools with clear descriptions, making it easier to choose the right agent
2. **No "agent not found" errors**: Tools are only registered for existing agents
3. **Simpler parameters**: Only `message` is needed, no need to specify agent name
4. **No naming conflicts**: The `agent_` prefix ensures tools don't conflict with other tools
5. **Semantic clarity**: Tool names clearly indicate they invoke agents

## Subagents

Subagents are defined in `.md` files with YAML frontmatter and can have:
- Custom prompts
- Specific tool sets
- Unique configurations
- Nested subagent delegation

To create a subagent, create a `.md` file in `~/.go-magnetar/agents/` or `{project}/.go-magnetar/agents/`.

See [agent_system.md](./agent_system.md) for complete documentation on creating and configuring subagents.

## Error Handling

Agent tools handle various error scenarios:

- **Empty message**: Returns an error if the message is empty
- **Agent execution error**: Returns an error if the subagent fails to execute

## Configuration

Agent tools are automatically generated for all non-disabled agents. To disable an agent (and its tool), set `disable: true` in the agent's YAML frontmatter:

```yaml
---
name: my-agent
description: My custom agent
disable: true
---
```

See [configuration.md](./configuration.md) for complete configuration options.
